# 02. 데이터베이스 관리 시스템이 필요한 이유 (Why DBMS Is Needed)

## 1. 데이터 관리의 필요성 (Need for Data Management)

### 한국어

- 고객 정보, 상품 정보, 주문 내역 등 다양한 데이터를 지속적으로 저장하고 관리해야 함
- 데이터의 양이 증가할수록 수작업으로 관리하기 어려워짐
- 데이터를 정확하고 효율적으로 저장·검색·수정할 수 있는 방법이 필요함

### 日本語

- 顧客情報（こきゃくじょうほう）、商品情報（しょうひんじょうほう）、注文履歴（ちゅうもんりれき）など、様々なデータを継続的（けいぞくてき）に保存（ほぞん）・管理（かんり）する必要（ひつよう）がある。
- データ量（りょう）が増加（ぞうか）するほど、手作業（てさぎょう）で管理（かんり）することが難（むずか）しくなる。
- データを正確（せいかく）かつ効率的（こうりつてき）に保存（ほぞん）・検索（けんさく）・更新（こうしん）する方法（ほうほう）が必要（ひつよう）になる。

## 2. 파일 시스템을 이용한 데이터 관리 (File-Based Data Management)

### 한국어

- 텍스트 파일이나 Excel 등을 이용하여 데이터를 저장하고 관리할 수 있음
- Excel은 행(Row)과 열(Column)을 이용해 데이터를 구조화할 수 있음
- 소규모 데이터 관리에는 유용하지만, 데이터가 많아지고 복잡해지면 한계가 발생함

### 日本語

- テキストファイルやExcelなどを利用（りよう）して、データを保存（ほぞん）・管理（かんり）できる。
- Excelでは、行（ぎょう）と列（れつ）を使（つか）ってデータを構造化（こうぞうか）できる。
- 小規模（しょうきぼ）なデータ管理（かんり）には便利（べんり）だが、データが増（ふ）えて複雑（ふくざつ）になると限界（げんかい）が生（しょう）じる。

### Example

```text
data/
├── customers.txt
├── products.txt
└── orders.txt
```

- 고객, 상품, 주문 데이터를 각각 별도 파일에 저장
- 여러 파일의 데이터를 함께 조회하거나 수정할 때 추가적인 처리 필요
- 顧客（こきゃく）、商品（しょうひん）、注文（ちゅうもん）のデータをそれぞれ別（べつ）のファイルに保存（ほぞん）する。
- 複数（ふくすう）のファイルのデータをまとめて検索（けんさく）・更新（こうしん）する場合（ばあい）、追加（ついか）の処理（しょり）が必要（ひつよう）になる。

## 3. 파일 시스템의 문제점 (Limitations of File Systems)

### 3.1 데이터 중복과 불일치 (Data Redundancy & Inconsistency)

- 동일한 데이터가 여러 파일에 중복 저장될 수 있음
- 일부 파일만 수정되면 동일한 데이터의 값이 서로 달라지는 불일치 문제 발생
- 同一（どういつ）のデータが複数（ふくすう）のファイルに重複（ちょうふく）して保存（ほぞん）される場合（ばあい）がある。
- 一部（いちぶ）のファイルだけを更新（こうしん）すると、同（おな）じデータの値（あたい）が異（こと）なる不整合（ふせいごう）が発生（はっせい）する。

### Example

```text
customers.xlsx
고객: Alice
주소: 서울시 마포구

orders.xlsx
고객: Alice
주소: 서울시 강남구
```

- 고객 주소가 두 파일에 중복 저장됨
- 한 파일만 수정되어 서로 다른 주소가 저장되는 문제 발생
- 顧客（こきゃく）の住所（じゅうしょ）が二（ふた）つのファイルに重複（ちょうふく）して保存（ほぞん）されている。
- 一方（いっぽう）のファイルだけが更新（こうしん）され、異（こと）なる住所（じゅうしょ）が保存（ほぞん）される問題（もんだい）が発生（はっせい）する。

### 3.2 데이터 접근의 어려움 (Difficulty of Data Access)

- 여러 파일에 저장된 데이터를 특정 조건으로 검색하기 어려움
- 복잡한 조회를 수행하려면 추가적인 프로그램이나 수작업이 필요할 수 있음
- 複数（ふくすう）のファイルに保存（ほぞん）されたデータを特定（とくてい）の条件（じょうけん）で検索（けんさく）することが難しい。
- 複雑（ふくざつ）な検索（けんさく）を行（おこな）うには、追加（ついか）のプログラムや手作業（てさぎょう）が必要（ひつよう）になる場合（ばあい）がある。

### 3.3 데이터 무결성 유지의 어려움 (Data Integrity)

- 데이터가 정해진 규칙을 만족하도록 관리하기 어려움
- 잘못된 값이나 중복된 값이 저장되는 문제를 방지하기 어려움
- データが定（さだ）められたルールを満（み）たすように管理（かんり）することが難（むずか）しい。
- 不正（ふせい）な値（あたい）や重複（ちょうふく）した値（あたい）が保存（ほぞん）される問題（もんだい）を防（ふせ）ぐことが難（むずか）しい。

### Example

```text
상품 가격: -1000
주문 수량: 0
중복 회원 ID: user01
```

- 상품 가격은 0보다 커야 함
- 주문 수량은 최소 1개 이상이어야 함
- 회원 ID는 중복되지 않아야 함
- 商品価格（しょうひんかかく）は0より大（おお）きくなければならない。
- 注文数量（ちゅうもんすうりょう）は最低（さいてい）1個（こ）以上（いじょう）でなければならない。
- 会員（かいいん）IDは重複（ちょうふく）してはならない。

### 3.4 동시성 제어 문제 (Concurrency Control)

- 여러 사용자가 동시에 동일한 데이터를 수정할 때 문제가 발생할 수 있음
- 적절한 동시성 제어가 없다면 데이터의 일관성이 깨질 수 있음
- 複数（ふくすう）のユーザーが同時（どうじ）に同（おな）じデータを更新（こうしん）すると、問題（もんだい）が発生（はっせい）する場合（ばあい）がある。
- 適切（てきせつ）な同時実行制御（どうじじっこうせいぎょ）がなければ、データの整合性（せいごうせい）が損（そこ）なわれる可能性（かのうせい）がある。


### Example

```text
초기 재고: 1개

운영자 A: 재고 1개 확인 → 주문 접수
운영자 B: 재고 1개 확인 → 주문 접수

결과: 재고는 1개인데 주문은 2건
```

- 두 운영자가 동일한 재고를 동시에 확인
- 재고보다 많은 주문이 접수되는 문제 발생
- 複数（ふくすう）のユーザーが同時（どうじ）に同じデータを更新すると、問題が発生する場合がある。
- 在庫数（ざいこすう）を超（こ）える注文（ちゅうもん）が受（う）け付（つ）けられる問題（もんだい）が発生（はっせい）する。

### 3.5 보안 문제 (Security)

- 파일 단위의 접근 권한만으로는 세밀한 데이터 접근 제어가 어려움
- 사용자별로 조회하거나 수정할 수 있는 데이터를 구분할 필요가 있음
- ファイル単位（たんい）のアクセス権限（けんげん）だけでは、細（こま）かなデータのアクセス制御（せいぎょ）が難（むずか）しい。
- ユーザーごとに閲覧（えつらん）・更新（こうしん）できるデータを区別（くべつ）する必要（ひつよう）がある。

### 3.6 백업 및 복구의 어려움 (Backup & Recovery)

- 파일이 손상되거나 삭제되면 데이터가 유실될 수 있음
- 장애 발생 시 데이터의 일관성을 유지하면서 복구하기 어려움
- ファイルが破損（はそん）したり削除（さくじょ）されたりすると、データが失（うしな）われる可能性（かのうせい）がある。
- 障害（しょうがい）が発生（はっせい）した際（さい）、データの整合性（せいごうせい）を維持（いじ）しながら復旧（ふっきゅう）することが難しい。

## 4. DBMS의 등장 (Emergence of DBMS)

- 파일 기반 데이터 관리의 문제점을 해결하기 위해 등장한 소프트웨어
- 데이터 저장, 검색, 수정, 삭제 등을 체계적으로 지원
- 데이터 무결성, 동시성 제어, 보안, 백업 및 복구 기능 제공
- 데이터 중복을 줄이고 일관성을 유지할 수 있도록 지원
- ファイルベースのデータ管理の問題点を解決するために登場したソフトウェア。
- データの保存、検索（けんさく）、更新（こうしん）、削除（さくじょ）などを体系的（たいけいてき）に支援（しえん）する。
- データの整合性（せいごうせい）、同時実行制御（どうじじっこうせいぎょ）、セキュリティ、バックアップ、復旧（ふっきゅう）の機能（きのう）を提供（ていきょう）する。
- データの重複（ちょうふく）を減（へ）らし、整合性（せいごうせい）を維持（いじ）できるように支援（しえん）する。

## Summary

- 파일 시스템은 소규모 데이터 관리에는 유용하지만 복잡한 데이터 관리에는 한계가 있음
- 주요 문제점은 중복과 불일치, 접근의 어려움, 무결성, 동시성, 보안, 백업 및 복구
- DBMS는 데이터를 체계적이고 효율적으로 관리하기 위한 소프트웨어
- DBMS는 데이터의 정확성, 일관성, 안전성을 유지하도록 지원
- ファイルシステムは小規模（しょうきぼ）なデータ管理（かんり）には便利（べんり）だが、複雑（ふくざつ）なデータ管理には限界（げんかい）がある。
- 主（おも）な問題点は、重複と不整合（ふせいごう）、アクセスの難しさ、整合性（せいごうせい）、同時実行制御（どうじじっこうせいぎょ）、セキュリティ、バックアップと復旧（ふっきゅう）である。
- DBMSは、データを体系的（たいけいてき）かつ効率的（こうりつてき）に管理（かんり）するためのソフトウェアである。
- DBMSは、データの正確性（せいかくせい）、整合性（せいごうせい）、安全性（あんぜんせい）の維持（いじ）を支援（しえん）する。
